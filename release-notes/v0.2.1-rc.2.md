# v0.2.1-rc.2 — Slot-only member controls and the upstream 0.1.28 host policy

Prerelease on npm `next`; the stable channel and the `latest` dist-tag stay on [v0.2.0](./v0.2.0.md). Recommended host: Harness `0.2.1-rc.4`; every host at or above `0.2.1-rc.2` is accepted.

- **Member page controls are pure slot contributions.** The model pill and the `/` command launcher render in the host composer's additive `conversation.input.right` list and read only this plugin's routes (`/member/models`, `/member/state`, `/member/commands`, `/member/relay`, `/member/model`). The host rewrites (`directoryFor`, the registered slot entry's `inject`, `directory.sessions`, `CommandDirectory.fetchCommands`, `CommandUiRuntime.execute`) are deleted. `conversation.input.model` is a single-owner slot: a second registration fails the whole client boot, so that seat stays with the host, which renders nothing for an addressed subagent session.
- **Upstream 0.1.28 host policy.** The package declares one install floor (`engines.dsh: >=0.2.1-rc.2`) and keeps every DSH peer at `*`, so a newer Harness release installs without a plugin release. `compatibility.json` stays the tested matrix (recommended `0.2.1-rc.4`, preview `0.2.1-rc.3`, legacy `0.2.1-rc.2`) and is no longer an allowlist. New maintenance commands: `pnpm check:upstream`, `pnpm sync:compatibility`.
- **A member command needs a resident member.** Within one host process a settled member stays resident (the inbox placeholder keeps its activation alive), so `/compact`, model switches and `agent_teams_run_command` work after a turn. After a host restart, or for an archived team, the member is a cold transcript and the command is refused with an explanation instead of resuming silently. The tool description and usage guide now state that contract.

```sh
dsh plugin --profile web add --save-exact @chenxu233/dsh-agent-teams@0.2.1-rc.2
```

Replace `web` with your CLI profile and restart that profile's Harness process after installation. The prerelease is opt-in; `latest` continues to resolve the stable `0.2.0` build.
