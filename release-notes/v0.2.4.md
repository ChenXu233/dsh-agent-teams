# v0.2.4 — Harness 0.2.2-rc.3 delivery contract; floor raised

Stable release on npm `latest`; the previous stable is [v0.2.3](./v0.2.3.md). Requires DeepSeek Harness `>=0.2.2-rc.3` — older hosts are rejected by the installer rather than loading a plugin that cannot deliver.

- **Members deliver through the host's new subagent contract.** Harness 0.2.2 removed the old `dsh.subagent.queuePrompt` / `deliverPrompt` symbols. Host-authored member turns now go through the runtime's `deliverPrompt(childId, content, { source, signal, delivery })`, preserving the queue/steer distinction and the plugin's own message source.
- **The retired-member guard covers every resume path.** Both `sendMessage` and the manager's `deliverPrompt` are wrapped, so a removed member cannot be resumed by a model message, a queued team turn, or a cold delivery. A delivery without a sender resolves the workspace from the session store or the host workspace registry.
- **Removing a member no longer depends on the retired targeted drain.** Harness 0.2.2 replaced `drainChildren` with a whole-tree `drainDescendants`; the plugin now interrupts the exact member ids instead of stopping the captain's unrelated subagents.
- **Provider diagnostics survive the facade trim.** `subagents.list()` is gone in 0.2.2, so the missing-provider error no longer assumes it.
- **Install floor.** `compatibility.json` now declares `minimumHost: 0.2.2-rc.3`, `engines.dsh` follows it, and the development host and pnpm overrides are pinned to 0.2.2-rc.3 / Cordis 4.1.0 / Schemastery 3.19.0. There is still exactly one floor and no host list.

The compatibility behavior above was exercised against the real `@deepseek-ai/dsh-subagent@0.2.2-rc.3` package: the guard installs and restores, queue and steer delivery route through `deliverPrompt`, and a retired target is rejected on both paths.

```sh
dsh plugin --profile web add --save-exact @chenxu233/dsh-agent-teams@0.2.4
```

Replace `web` with your CLI profile and restart that profile's Harness process after installing.

## 中文

npm `latest` 上的正式版；上一版为 [v0.2.3](./v0.2.3.md)。安装下限提高到 DeepSeek Harness `>=0.2.2-rc.3`，更老的宿主会被安装器拒绝，而不是装上一个无法投递成员轮次的插件。

- **成员投递适配宿主的新契约。** Harness 0.2.2 移除了旧的 `dsh.subagent.queuePrompt` / `deliverPrompt` 符号，成员轮次改走 runtime 的 `deliverPrompt(childId, content, { source, signal, delivery })`，队列/steer 语义与插件自己的消息来源都保留。
- **退役成员守卫覆盖全部恢复路径。** `sendMessage` 与 manager 的 `deliverPrompt` 都被包住：模型消息、排队的团队轮次、冷投递都无法唤醒已移除的成员。没有 sender 的投递会从会话存储或宿主工作区注册表解析工作区。
- **移除成员不再依赖被删掉的定向 drain。** 0.2.2 用整树 `drainDescendants` 取代了 `drainChildren`；插件改为按成员 id 定向 `interrupt`，不会顺带停掉队长的其他子代理。
- **provider 诊断适配 facade 收窄。** 0.2.2 移除了 `subagents.list()`，provider 缺失的报错不再假设它存在。
- **安装下限。** `compatibility.json` 现在声明 `minimumHost: 0.2.2-rc.3`，`engines.dsh` 随之一致，开发宿主与 pnpm overrides 固定到 0.2.2-rc.3 / Cordis 4.1.0 / Schemastery 3.19.0。仍然只有一个下限，没有宿主清单。

以上兼容行为已在真实的 `@deepseek-ai/dsh-subagent@0.2.2-rc.3` 包上验证：守卫可安装与还原，队列和 steer 都走 `deliverPrompt`，退役目标在两条路径上都被拒绝。

```sh
dsh plugin --profile web add --save-exact @chenxu233/dsh-agent-teams@0.2.4
```
