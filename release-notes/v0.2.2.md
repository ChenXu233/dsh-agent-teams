# v0.2.2 — Delete an archived team

Stable release on npm `latest`; the previous stable is [v0.2.1](./v0.2.1.md). Requires DeepSeek Harness `>=0.2.1-rc.2` — unchanged, so upgrading needs no configuration change.

- **An archived team can be deleted (#223-③).** The team view grew a delete control on every ended team: a confirm dialog states that the removal is permanent, then the host removes `<stateDir>/archive/<teamId>/` and reports `deleted`. Until now an ended team occupied the panel forever and only a manual `rm -rf` could clear it.
- **The delete is guarded on the host, not just in the dialog.** `removeArchivedTeamDir` refuses an id that is not a plain directory name, an id that was never archived, and an id a live team still owns — the active directory is never touched, because a re-run team may be writing into a freshly created archive of the same id. The deletion runs under the per-team lock, so it stays serial with archive and dispose. `POST /plugins/dsh-agent-teams/team/archive/delete` takes `{ workspacePath, teamId }`, requires a workspace the registry reports, and answers 400/404/409 for the three refusals.
- **The control is where people look.** The first cut wired it only into the floating panel; "View team" opens the workspace tab, which had no affordance. Both surfaces now share one request helper, so the row disappears immediately instead of waiting for a poll.
- **Archived teams survive a reload.** The activity monitor fetches the archive list once per controller rather than only on a live→archived transition, so a team archived before the page loaded is still listed and still deletable.

```sh
dsh plugin --profile web add --save-exact @chenxu233/dsh-agent-teams@0.2.2
```

Replace `web` with your CLI profile and restart that profile's Harness process after installing. The install floor, the peer declaration and every existing configuration key are unchanged from [v0.2.1](./v0.2.1.md).

## 中文

正式版新增「删除已归档团队」（upstream #223-③）：结束的团队在团队视图里带删除按钮，二次确认后由宿主删除 `<stateDir>/archive/<teamId>/`，**不可恢复**。宿主侧有守卫——非目录名、未归档、同 id 的活动团队仍存在时一律拒绝，删除在团队锁下串行执行。

这一版还修了两个让按钮够不着的问题：控件此前只接在浮层上，而「查看团队」打开的是工作区标签页；以及刷新前就已归档的团队不会被列出。现在两个界面共用一个请求helper，归档列表在每次轮询控制器启动时拉取一次。

升级不需要改配置：安装下限、peer 声明和所有配置项都与 v0.2.1 相同。
