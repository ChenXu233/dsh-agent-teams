# v0.2.1 — One compatibility floor and slot-only member controls

Stable release on npm `latest`; the previous stable is [v0.2.0](./v0.2.0.md). Requires DeepSeek Harness `>=0.2.1-rc.2`: every later host — RC, prerelease or stable — installs without a plugin release.

- **Compatibility is one declared floor.** [compatibility.json](../compatibility.json) is schema v2 and carries a single `minimumHost`. The enumerated `supportedHosts` list and the `recommendedHost` pointer are gone, and a leftover field now fails validation instead of sitting in the file as dead policy. `engines.dsh` publishes `>=0.2.1-rc.2` and every DSH peer stays `*`. CI exercises the floor by default; `workflow_dispatch` accepts one extra exact host to test without editing any file.
- **Member page controls are pure slot contributions.** Shipped in 0.2.1-rc.1/rc.2 and stable here: the model pill and the `/` command launcher render into the host composer's additive `conversation.input.right` list and call only this plugin's routes. No host service is patched. `conversation.input.model` is a single-owner slot, so that seat stays with the host.
- **A member command needs a resident member.** Within one host process a settled member stays resident; after a host restart, or for an archived team, the member is a cold transcript and the command is refused with an explanation instead of resuming silently.
- **Verification is one entry point.** `pnpm verify` runs [scripts/verify-all.mjs](../scripts/verify-all.mjs): 24 named phases that run in order and stop at the first failure.
- **A smaller package.** Two modules with no remaining callers (`member-menu`, `member-select`) no longer ship in `lib/`.
- **Docs.** The dated audit evidence that had accumulated next to the live guides now lives in [`docs/archive/`](../docs/archive/README.md).

```sh
dsh plugin --profile web add --save-exact @chenxu233/dsh-agent-teams@0.2.1
```

Replace `web` with your CLI profile and restart that profile's Harness process after installing. Upgrading from [v0.2.0](./v0.2.0.md) needs no configuration change: the install floor is the same and the plugin keeps one peer declaration for every DSH version.
