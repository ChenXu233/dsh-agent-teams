# v0.2.6 — install proton in one command

Stable release on npm `latest`; the previous stable is [v0.2.5](./v0.2.5.md). No protocol, tool or member behaviour changed — this release carries the packaging and documentation fixes that landed after 0.2.5.

- **The model seat now requires a proton that mounts itself.** `dsh-proton-adapter-dsh@^0.1.6` ships a non-empty bundle patch, so `dsh plugin add` composes the entry. `0.1.5` shipped an empty patch and needed two hand-written `insert` rows in the profile's `cordis.patch.yml`; the floor is raised so the documented one-command install is true by construction rather than by convention.
- **The install note inside the published package is corrected.** The 0.2.5 tarball carried a paragraph telling readers to hand-write those rows. npm artifacts are immutable, so the correction could only ride the next release; the [v0.2.5 release page](https://github.com/ChenXu233/dsh-agent-teams/releases/tag/v0.2.5) was updated in place.
- **Nothing else moves.** The member model router, the fallback pill's stand-down rule and `compatibility.json` are unchanged, and the Harness floor stays `minimumHost: 0.2.2-rc.3`. The native seat is still optional: without the proton packages the plugin behaves exactly as before.

The native seat needs both proton packages installed; each mounts itself from 0.1.6 on:

```sh
dsh plugin --profile web add dsh-proton dsh-proton-adapter-dsh
```

```sh
dsh plugin --profile web add --save-exact @chenxu233/dsh-agent-teams@0.2.6
```

Replace `web` with your profile and restart that profile's Harness process after installing.

**Verification scope.** `pnpm verify` passes all phases; the router and member-route tests are unchanged from 0.2.5. Real-window interaction with the model picker on a member page remains **not** exercised — this environment cannot drive the desktop GUI. That gap is unchanged and is not claimed as passing.

## 中文

npm `latest` 上的正式版；上一版为 [v0.2.5](./v0.2.5.md)。协议、工具与成员行为都没有变化——这一版只带上 0.2.5 之后落地的打包与文档修正。

- **模型座位改成要求「自带挂载」的质子。** `dsh-proton-adapter-dsh@^0.1.6` 的 bundle patch 不再是空数组，`dsh plugin add` 装完就会把组合行加进去。`0.1.5` 是空 patch，必须在 profile 的 `cordis.patch.yml` 里手写两行 `insert`；把下限抬上来，是为了让「一条命令装完」成为构造上的事实，而不是一句约定。
- **发布产物里那段安装说明改对了。** 0.2.5 的 tarball 里写着要手写那两行；npm 产物不可变，所以只能随下一版发出，同时把 [v0.2.5 的 Release 页面](https://github.com/ChenXu233/dsh-agent-teams/releases/tag/v0.2.5)就地更新。
- **其余不动。** 成员模型 router、备用药丸的让位规则、`compatibility.json` 都没改，Harness 下限仍是 `minimumHost: 0.2.2-rc.3`。原生座位依旧是可选的：不装质子那两个包，插件行为与之前完全一致。

原生座位需要两个质子包都装上；0.1.6 起每个包自己负责挂载：

```sh
dsh plugin --profile web add dsh-proton dsh-proton-adapter-dsh
```

```sh
dsh plugin --profile web add --save-exact @chenxu233/dsh-agent-teams@0.2.6
```

**验证边界。** `pnpm verify` 全部阶段通过；router 与成员路由用例与 0.2.5 相同。真实窗口里在成员页点模型选择器仍然**没有**验过——本环境驱动不了桌面 GUI。这条缺口没有变化，也不写成通过。
