# v0.2.5 — the member model switcher becomes the host's own seat

Stable release on npm `latest`; the previous stable is [v0.2.4](./v0.2.4.md). The install floor is unchanged at DeepSeek Harness `>=0.2.2-rc.3`.

- **The host's model seat now serves member pages.** The shipped `conversation.input.model` entry is fenced for addressed subagent sessions: its inject face answers `available: false`, so the picker renders nothing there, and `load()` / `select()` throw out of the fenced directory. That seat is now taken over through `dsh-proton-adapter-dsh`, which re-renders whichever entry won it — the shipped `ModelSelect` or `@hytime/dsh-thinking-effort`'s `Slider` — with this plugin's routing swapped in. Neither occupant is displaced or re-registered; proton shadows the seat at a lower priority and draws the winner back.
- **The seat is no longer implemented here.** The official slot key, the kit assembly, the priority contest and the `kitTap` seam live in `dsh-proton-adapter-dsh@^0.1.5`. This plugin registers one router through `ctx.protonModelSeat.addRouter()` and answers one question: for a session it has proven to be its own member, replace `available` (so the picker renders), `load` (the fenced directory throws on both shipped entries) and `select` (to `POST /member/model`). `directory` is left alone, so the model groups, their reasoning metadata and the session's own selection projection stay the host's.
- **Every other session is byte-for-byte unchanged.** The router returns `undefined` for anything that is not a proven member — other plugins' subagent pages included — and the adapter only mounts the seat while a router exists. A profile without `dsh-proton-adapter-dsh` behaves exactly as 0.2.4 did.
- **The additive model pill becomes the fallback.** When the native seat routes a member page, the `conversation.input.right` pill stands down, so a member conversation never shows two model controls.
- **One new dependency, no new floor.** `dsh-proton-adapter-dsh` is a plugin dependency, not a host requirement: `compatibility.json` and `engines.dsh` are untouched.

The native seat needs proton mounted in the profile (optional — without it the fallback pill is used):

```sh
dsh plugin --profile web add dsh-proton dsh-proton-adapter-dsh
```

```sh
dsh plugin --profile web add --save-exact @chenxu233/dsh-agent-teams@0.2.5
```

Replace `web` with your CLI profile and restart that profile's Harness process after installing.

**Verification scope.** The router's answers and the member route are covered by `pnpm verify`; the seat's routing and its reference-counted mount are covered by proton's own test suite. Real-window interaction — clicking the picker on a member page, focus, HMR and unmount — was **not** exercised: this environment cannot drive the desktop GUI. That gap is recorded here rather than claimed as passing.

## 中文

npm `latest` 上的正式版；上一版为 [v0.2.4](./v0.2.4.md)。安装下限不变，仍是 DeepSeek Harness `>=0.2.2-rc.3`。

- **成员页改用宿主自己的模型座位。** 宿主那条 `conversation.input.model` 对寻址子代理会话是被围起来的：它的注入面回答 `available: false`，所以选择器在成员页整块渲染 `null`，`load()` / `select()` 直接抛错。这个座位现在由 `dsh-proton-adapter-dsh` 接管——它把胜出的那条重新渲染一遍（官方 `ModelSelect` 或 `@hytime/dsh-thinking-effort` 的 `Slider`），只把本插件的路由换进去。两个占用者都没被挤走或重新注册：质子以更低的优先级占座，再把胜者请回来画。
- **座位不再由本插件实现。** 官方 slot key、kit 组装、优先级竞争和 `kitTap` 缝都在 `dsh-proton-adapter-dsh@^0.1.5` 里；本插件只通过 `ctx.protonModelSeat.addRouter()` 注册一条 router，回答一个问题：对已证明确属自己的成员会话，替换 `available`（不替换选择器根本不画）、`load`（被围起来的目录在两条 entry 上都会抛）、`select`（转 `POST /member/model`）。`directory` 原样不动，模型分组、推理档位元数据和该会话自己的选择投影继续用宿主那份。
- **其余会话一个字节都不变。** 非成员会话（含其他插件的子代理页）一律返回 `undefined`，适配层也只在有 router 时挂载座位；没装 `dsh-proton-adapter-dsh` 的 profile 与 0.2.4 完全一致。
- **加法式模型药丸降级为备用。** 原生座位接管成员页时，`conversation.input.right` 上那个药丸让位，一次不会出现两个模型控件。
- **多了一个依赖，但下限没动。** `dsh-proton-adapter-dsh` 是插件依赖而不是宿主要求，`compatibility.json` 与 `engines.dsh` 都未修改。

原生座位需要在 profile 里挂载质子（可选——不装就用备用药丸）：

```sh
dsh plugin --profile web add dsh-proton dsh-proton-adapter-dsh
```

**验证边界。** router 的答案与成员路由由 `pnpm verify` 覆盖；座位的路由与按需挂载由质子自己的测试覆盖。真实窗口里的点击、焦点、HMR 与卸载**没有**做——本环境无法驱动桌面 GUI。这条缺口记在这里，不写成「全部通过」。
