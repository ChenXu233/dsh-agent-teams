# v0.2.0 — Member page, durable residency and the fork's own identity

Stable plugin release on npm `latest`; recommended host: Harness `0.2.1-rc.4`. Every host at or above `0.2.1-rc.2` is accepted, including newer releases, RCs and prereleases.

- Take the fork's own identity: the package is `@chenxu233/dsh-agent-teams`, the Cordis patch, plugin source name, sidebar tab id and repository metadata follow it.
- Replace the enumerated host matrix with a single floor. Every Harness peer now declares `>=0.2.1-rc.2`, and the development baseline moves to `0.2.1-rc.4` (lockfile rebuilt so the whole dependency cohort matches the host).
- Members stay resident after a turn settles: a parked `next-step` placeholder keeps the child session alive and is removed synchronously when real work arrives.
- The member page owns the member conversation. The host composer cannot run commands in a subagent-owned session, so the plugin serves its own `agentTeams` Remote namespace and HTTP routes: model switch, queue badge, stop, command menu, and a read-only composer once the member is archived.
- Retire the activity panel's duplicate member inputs; the composer is the only place a member is operated.
- Pin only a real reasoning choice. A model default the host materializes is no longer written into `team.json` as though the user had picked it, and a pinned route now survives a deployment-wide subagent effort policy (for example a "thinking effort" plugin that forces every subagent to one level).

In desktop plugin settings, install `@chenxu233/dsh-agent-teams@0.2.0` and enable it. Follow the host's restart prompt when appropriate for your running work. For a CLI-managed profile:

```sh
dsh plugin --profile web add --save-exact @chenxu233/dsh-agent-teams@0.2.0
```

Replace `web` with your CLI profile and restart that profile's Harness process after installation. Plugin and host versions are independent; this release does not upgrade the host.
